# SimTuning for iOS (`apps/apple`)

Native iOS 18 app (SwiftUI, Swift 6 strict concurrency) for SimTuning v3. Layout mirrors the
luki-fitti Apple workspace: XcodeGen project + local Swift package. The generated
`SimTuning.xcodeproj` is not committed.

```
apps/apple
├── project.yml                 XcodeGen spec (SimTuningIOS, SimTuningIOSUITests)
├── Config/*.xcconfig           API base URL per configuration (Debug: localhost:3001)
├── Packages/SimTuningKit       Swift package
│   ├── SimTuningLogic          ports of packages/common logic, units, rounding, audio DSP
│   ├── SimTuningAPI            Codable DTOs, validation, URLSession client, Keychain tokens
│   └── SimTuningStore          offline guest repository (JSON file) + API repository
├── SimTuningIOS                SwiftUI app (Fahrzeuge, Motor, Einlass, Auslass, Dyno, Profil)
├── SimTuningIOSUITests         guest-mode smoke tests
└── scripts/generate-app-icon.swift
```

## Commands

```sh
yarn workspace @sim-tuning/apple test        # swift test (includes the v2 golden parity tests)
cd apps/apple && xcodegen generate
xcodebuild -project SimTuning.xcodeproj -scheme SimTuningIOS \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
yarn workspace @sim-tuning/apple test:e2e:ios  # UI tests on a simulator
```

`SIMTUNING_API_BASE_URL` (environment variable) overrides the xcconfig value; only HTTPS or
`http://localhost` is accepted. Signing: set your team locally in Xcode, never commit it.

## Design ("Werkstattzeichnung")

Tokens from `DESIGN.md` (repository root) live in `SimTuningIOS/Design/Theme.swift`: adaptive
dark/light colours with Increase Contrast variants, module colours (`Module`), fonts
(`.stHeading` condensed SF Pro, `.stData` SF Mono, `.stUnit` small caps), spacing and the 4 pt
radius. `Design/Werkstatt.swift` holds the Schriftfeld (title block), Callout, Stückliste, drawing
grid and draw-in helpers; `Design/ChartStyle.swift` styles Swift Charts. Screens use `SheetForm` /
`SheetList` (grouped lists on the drafting-table background). New installs start dark; Profil ›
Design can switch to light or follow the system.

Design screenshots from the UI tests (Steuerdiagramm, Auspuff, dark and light):

```sh
TEST_RUNNER_SIMTUNING_SCREENSHOT_DIR=$PWD/.build/screenshots xcodebuild test \
  -project SimTuning.xcodeproj -scheme SimTuningIOS -destination 'id=<simulator udid>'
```

## Parity

`Tests/SimTuningLogicTests/Fixtures` are byte-identical copies of
`packages/common/src/__fixtures__` (`v2-golden.json`, `dyno-acceleration.wav`). The Swift tests
assert the same values as `packages/common/src/{logic,audio}/v2-parity.spec.ts` and
`units/units.spec.ts` (exact equality where TS uses `equal`), so .NET v2, TypeScript and Swift
are pinned to the same numbers. Keep the fixtures in sync when the TS fixtures change.

## Deferred

- Unit pickers per field (values are entered in fixed display units, stored in base units; the
  rounding preferences apply to results).
- Sync of guest data into an account after sign-in (guest and account data are separate, as on
  the web). Email verification / password reset deep links and account deletion UI.
- Environment management UI (starter environments can be assigned to a dyno; the repository
  supports create/update/delete).
- GPS speed/coast-down curve fitting (v2 had it disabled as well); GPS runs are recorded and
  stored as samples.
- In-app language switching applies to SwiftUI texts; strings created with `String(localized:)`
  follow the system language.
- Final app icon artwork (placeholder generated by `scripts/generate-app-icon.swift`).
